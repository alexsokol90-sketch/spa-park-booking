# СПА-парк: онлайн-запись и круглосуточный ИИ-ассистент в MAX

Прототип для хакатона «Код Югры — Цифровой вызов» (Сургут, 14–15.11.2026).
Заказчик — спа-центр «СПА-парк» в Нижневартовске (ул. Индустриальная, 46).

Сейчас запись ведётся вручную в Google-таблице. Прототип заменяет её базой данных с собственным интерфейсом и добавляет:

- **ассистента в мессенджере MAX**: работает круглосуточно, понимает свободный текст и кнопки, отвечает на русском и английском;
- **сетку администратора**: живое обновление, захваты слотов с обратным отсчётом, карточки броней;
- **автоматическое подтверждение визитов**: запрос гостям в 10:00, список неответивших для обзвона в 15:00;
- **маркетинговый модуль**: сегменты базы, предпросмотр, рассылки; учитывается согласие гостя на рекламу.

## Как устроена защита от накладок

1. **Показ окна.** Ассистент показывает 3–5 реально свободных окон. Учитывается занятость пространства (программа плюс уборка) и мастера (только время программы).
2. **Захват на 15 минут.** В таблицу `bookings` вставляется строка со статусом `hold`. Целостность обеспечивает PostgreSQL:
   - `EXCLUDE USING gist (space_id WITH =, tstzrange(starts_at, busy_until) WITH &&)` — два захвата или брони не пересекаются в одном пространстве;
   - `EXCLUDE USING gist (master_id WITH =, tstzrange(starts_at, ends_at) WITH &&)` — у мастера не бывает двух гостей одновременно;
   - `UNIQUE (guest_id) WHERE status = 'hold'` — у гостя может быть только один активный захват.
3. **Подтверждение брони.** Подтвердить можно только живой захват. Если захват истёк, бронь не создаётся и гость получает новые окна.

Если бот и ресепшен одновременно захватывают одно окно, второй запрос получает от базы ошибку `ExclusionViolation`. Ассистент сразу предлагает 3 ближайших варианта: ту же программу в пределах ±2 часов или похожую программу в то же время. Если вариантов нет, диалог уходит администратору с пометкой о желаемом времени.

Просроченные захваты снимаются автоматически каждые 5 секунд. За 2 минуты до истечения захвата администратор получает предупреждение. Сетка обновляется мгновенно через SSE, а для страховки ещё и раз в 10 секунд.

## Требования кейса → реализация

| Требование | Где реализовано |
|---|---|
| Ночью заявки принимаются, создаются реальные брони | `dialog.py`; в подтверждении указано, что администратор на связи с 10:00 |
| ≥80% типовых вопросов без человека | База знаний `kb.py`; разбор текста без модели `nlu.py`; ИИ-агент `ai.py` |
| Подтверждение визита в 10:00, список неответивших в 15:00 | `scheduler.py`, вкладка «Обзвон» |
| Тайминги программ и уборки в цифрах | `programs.duration_min`, `programs.cleanup_min`; уборка показана в сетке |
| Ноль накладок | EXCLUDE-ограничения, тест `test_concurrent_holds_only_one_wins` |
| База гостей как инструмент возврата | `marketing.py`: именинники, «не были 90+ дней», активные |
| Согласия (факт, дата, версия, канал) | Таблица `consents`; согласие запрашивается перед первой бронью |
| Эскалация на администратора | `escalation.py`: жалобы — высокий приоритет, группы, здоровье, «не понял дважды»; повторное уведомление через 5 мин |
| Предзаказ (чай, добавки в ванну) | `booking_preorders`, вкладка «Расход на день», карточка брони |
| Без медицинских решений, без выдуманных цен | Системный промпт и инструменты: модель берёт данные только из каталога и базы знаний |
| Ручное подтверждение оплаты | Карточка брони: карта, наличные, ресепшен отеля, онлайн, сертификат |
| Все ветки диалога | Программы по пространствам, цены, запись, адрес и как добраться, парковка, часы, противопоказания, сертификаты, СПА для двоих, компании и девичники (сбор пожеланий → администратор), моя запись, спа-этикет, акции, администратор |
| Пятишаговая запись | Свободный текст → 3–5 окон → захват → телефон (гость подтягивается из базы), имя, галочки согласий → подтверждение с адресом, мастером, длительностью, этикетом и условиями отмены |
| Напоминания | 10:00 за сутки (подтверждение + предзаказ), 15:00 список неответивших, за 2–3 часа с адресом, через день после визита (благодарность + отзыв) |
| Маркетинговые сценарии | День рождения за 5–7 дней, реактивация (N дней, программа по истории), анонсы по любимому пространству и сумме трат, после визита, брошенная бронь; персонализация моделью, предпросмотр, отписка |
| Журнал доступа к ПДн | Таблица `pd_access_log`: каждый просмотр гостя, брони, диалога, выгрузка, удаление, рассылка |
| Версии текстов согласий | Таблица `consent_texts` + в каждой отметке версия, дата, время, канал |
| Выгрузка и удаление данных | Карточка гостя: JSON-выгрузка; удаление — переписка стирается, профиль обезличивается, будущие записи отменяются |
| Тайминги | `duration_min` (программа), `master_min` (время мастера — по сайту, например «мастер 30 мин + чайная церемония»), `cleanup_min` (уборка): мастер освобождается раньше пространства |
| RU/EN и термины | Язык определяется по сообщению; названия и описания программ на английском; глоссарий: hammam, steaming with brooms, body wrap, milk bath |

## Каналы

Один движок диалога (`dialog.py`) — несколько транспортов:

| Канал | Модуль | Статус |
|---|---|---|
| MAX | `max_bot.py` | готов, ждёт токен (бизнес-верификация и модерация бота занимают около суток) |
| Telegram | `tg_bot.py` | работает: inline-кнопки, запрос контакта, HTML-разметка |
| ВКонтакте | `vk_bot.py` | работает: callback-кнопки с учётом лимитов VK (6 рядов, 10 кнопок) |
| Веб-эмулятор | `web/index.html` | работает без токенов |

Гость определяется по идентификатору канала. После того как он сообщит телефон, профиль объединяется с базой гостей, так что один гость может писать из разных мессенджеров. Уведомления администратора уходят во все подключённые каналы: в чат, где выполнена команда `/admin <пароль>`.

## Архитектура

```
MAX ──long polling──┐
                    ├─► dialog.py (сценарии + кнопки) ─► booking.py ─► PostgreSQL (EXCLUDE)
Веб-эмулятор чата ──┘        │                               ▲
                             └─► ai.py (Claude + инструменты) │
Интерфейс администратора ─► main.py (FastAPI, SSE) ──────────┘
scheduler.py: захваты, напоминания, отчёт 15:00, дни рождения
```

- **Гибридный ввод.** Кнопки работают всегда. Свободный текст разбирают правила (`nlu.py`), а при наличии ключа — Claude с инструментами `find_slots`, `hold_slot`, `my_bookings` и `escalate`. Модель не может подтвердить бронь сама: это делает только гость кнопкой «Подтвердить».
- **Английский.** Язык определяется по тексту гостя, ответы и названия программ даются на английском. Ключевые термины переводятся по глоссарию: хаммам, парение, обёртывание, молочная ванна.

## Запуск

```bash
sudo apt install postgresql postgresql-contrib
sudo -u postgres psql -c "CREATE ROLE spa LOGIN PASSWORD 'spa'" -c "CREATE DATABASE spa OWNER spa"
sudo -u postgres psql -d spa -c "CREATE EXTENSION btree_gist"

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # заполните ADMIN_PASSWORD, MAX_BOT_TOKEN, ANTHROPIC_API_KEY
.venv/bin/python -m app.seed  # демо-каталог: 7 пространств, 35 программ, 6 мастеров, гости
.venv/bin/uvicorn app.main:app --port 3030
```

- `/` — веб-эмулятор чата MAX (тот же движок диалога);
- `/admin` — интерфейс администратора (HTTP Basic).

Чтобы получать уведомления администратора в MAX, задайте `MAX_ADMIN_CHAT_ID` или напишите боту в нужном чате `/admin_here <ADMIN_PASSWORD>`.

Тесты (нужна база с демо-данными):

```bash
.venv/bin/python -m pytest -q
```

## Размещение в РФ

- **Сервер:** российское облако (Timeweb Cloud, Москва), Ubuntu 24.04. Развёртывание одной командой: `DOMAIN=... bash deploy/setup.sh` (PostgreSQL, приложение под systemd, HTTPS через Caddy и Let's Encrypt, файрвол — только SSH и HTTPS).
- **Языковая модель:** GigaChat (`app/gigachat.py`), TLS с корневым сертификатом НУЦ Минцифры, проверка сертификатов не отключается. Claude оставлен как альтернативный провайдер (`LLM_PROVIDER`).
- **Минимизация ПДн в модели:** телефоны маскируются, в промпт уходит только имя гостя.
- **Обязанности оператора ПДн** (уведомление Роскомнадзора, политика обработки, договор поручения обработки с разработчиком) выполняет заказчик — ООО «Парк Сайд инн».
